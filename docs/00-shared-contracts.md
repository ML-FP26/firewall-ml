# 00 — Shared contracts (the law of the repo)

Everything in this file is a **contract**. A PRD says *what* you produce and *what you may rely on*. This file says exactly *what the artifacts look like*, so nobody ever needs to ask "how did you do it?". If you depend on an artifact, you read its row here and nothing else. If you produce one, you match its row exactly.

## 1. Decisions locked (do not reopen without telling Nafi)

| # | Decision | Value |
|---|---|---|
| D1 | Dataset | UCI **Internet Firewall Data**, id 542, DOI 10.24432/C5131M, licence CC BY 4.0 (credit UCI in README) |
| D2 | Task | Multiclass classification of the firewall `action` from the other 11 columns |
| D3 | Models | `rf` = RandomForestClassifier, `gb` = HistGradientBoostingClassifier, `logreg` = LogisticRegression (baseline). `knn` is an optional extra, same contract. No deep learning. |
| D4 | Split | Drop exact duplicates **first**, then stratified 80/20 split, `RANDOM_STATE = 42`. The test set is scored **once per model**. |
| D5 | Tuning | 5-fold `StratifiedKFold(shuffle=True, random_state=42)` on the **train** file only. Tuning score = `f1_macro`. |
| D6 | Primary metric | **macro-F1** (so the rare class counts). Also reported: accuracy, weighted-F1, balanced accuracy, MCC, per-class precision/recall/F1, confusion matrix. |
| D7 | Scaling | `load_split()` returns **raw, unscaled** features. Any scaling lives *inside* the model's sklearn `Pipeline` (so it is fit on training folds only). |
| D8 | Best model | Chosen by **CV macro-F1 mean**, never by test score. Test numbers are reported, not used to pick. |
| D9 | Rare class | Default: **keep all 4 classes**. A may change this only before the data freeze, with Nafi's OK, and must record why in `docs/decisions/rare-class.md`. |

## 5. Model contract

### 5.1 `src/models/<name>.py` (producers B2, C2, D2)

```python
NAME: str                  # "rf" | "gb" | "logreg" | (optional) "knn"
PARAM_GRID: dict           # keys use the pipeline step prefix, e.g. "clf__max_depth"
SEARCH: str = "grid"       # "grid" or "random"
N_ITER: int | None = None  # only for SEARCH == "random"

def build_model(**overrides) -> sklearn.base.BaseEstimator:
    """Unfitted estimator or Pipeline. Sets random_state=42 wherever the
    estimator supports it. Scaling (if needed) is a step INSIDE the Pipeline.
    `overrides` are passed to the classifier (e.g. class_weight='balanced')."""
```
Nothing else. A model owner never touches splitting, CV, or metrics code.

### 5.2 `src/runner.py` (producer N2)

```python
def list_models() -> list[str]                      # every module in src/models/
def run(name: str, use_saved_params: bool = False) -> dict   # writes results/<name>/*, returns metrics dict
def get_fitted_model(name: str)                     # loads results/<name>/model.joblib,
                                                    # else refits from best_params.json
# CLI:  python -m src.runner <name> [--use-saved-params]
```

What `run()` does, in this order and nothing else: `load_split()` → `check_cv_feasible()` → search with `build_model()`, `PARAM_GRID`, `get_cv()`, `SCORING` (or load `best_params.json` when `use_saved_params`) → refit on the full train file → predict on test **once** → `evaluate()` → write files.

**Files written per model** (`results/<name>/`):

| File | Committed? | Contents |
|---|---|---|
| `best_params.json` | yes | `{"clf__max_depth": 20, ...}` |
| `cv_results.csv` | yes | sklearn `cv_results_` as csv |
| `metrics.json` | yes | schema below |
| `preds.csv` | yes | columns `row_id, y_true, y_pred, proba_<label>...` (`row_id` = row number in `test.csv`) |
| `model.joblib` | **no** (gitignored) | fitted estimator; regenerate with `--use-saved-params` |

`metrics.json`:

```json
{
  "model": "rf",
  "labels": ["..."],
  "n_train": 0, "n_test": 0,
  "cv": {"scoring": "f1_macro", "n_splits": 5, "mean": 0.0, "std": 0.0},

    "accuracy": 0.0, "macro_f1": 0.0, "weighted_f1": 0.0,
```

`confusion_matrix`: rows = true class, columns = predicted class, both in `labels` order.

## 6. Analysis and docs contracts

### 6.1 Comparison — `results/comparison.csv` (producer N3 via `src/compare.py`)
One row per model found in `results/*/metrics.json`. Columns:
`rank_by_cv, model, cv_macro_f1_mean, cv_macro_f1_std, test_accuracy, test_macro_f1, test_weighted_f1, test_balanced_accuracy, test_mcc, fit_seconds, recall_<label> (one column per label)`.
Sorted by `cv_macro_f1_mean` descending; `rank_by_cv` starts at 1. `figures/comparison.png` (A) is a chart of this file.

### 6.2 Top features — `results/feature_importance.csv` (producer B3)
Columns: `feature, impurity_importance, perm_importance_mean, perm_importance_std`.
Permutation importance: on the **test** set, `scoring="f1_macro"`, `n_repeats=10`, `random_state=42`. Sorted by `perm_importance_mean` descending. Plus `figures/feature_importance.png`.

### 6.3 Imbalance test — `results/imbalance_ablation.csv` (producer C3)
Model = `gb` only. Columns: `variant, cv_macro_f1_mean, cv_macro_f1_std, test_accuracy, test_macro_f1, recall_<label>...`.
Variants: `none`, `class_weight_balanced` (required); `smote_in_cv` (optional, must live inside the CV pipeline). Same `get_cv()`, same `evaluate()`. Plus `figures/imbalance_ablation.png`.

### 6.4 Error analysis (producer D3)
- `results/per_class_recall.csv` — long format: `model, label, precision, recall, f1, support`, built from every `metrics.json`.
- `results/misclassified_best.csv` — test rows the CV-best model got wrong: `row_id, y_true, y_pred, <FEATURES...>`.
- `figures/confusion_<model>.png` — one per model, row-normalised.
- `reports/error_analysis.md` — answers: which class breaks the models, why (with evidence from the features), and what would help.

### 6.5 Other reports
- `reports/leakage_audit.md` (A3): checklist with pass/fail per check (see PRD A).
- `reports/data_findings.md` (A4): data-side findings (duplicates, conflicting rows, skew, which columns look uninformative), with numbers from `counts.json` and `freeze.json`.
- `docs/model-cards/<name>.md`: what the model is, why it fits, the search space, the best params, CV and test numbers (copied from `metrics.json`, never retyped), one honest weakness.

## 8. Rules that make the contracts hold

1. **Test discipline.** Nothing is tuned, selected, or decided using test scores. CV on train decides; test only reports.
2. **Fix the seed.** `random_state=42` everywhere it is accepted.
3. **No copy-pasted numbers.** Numbers come from `results/*.json|csv`.
4. **Consume outputs only.** If you need something that isn't in a registry row, ask the producer to add it to their output. Do not read their internals.
5. **Contract changes.** If an output has to change after others depend on it: the owner (a) tells Nafi, (b) bumps the version in `docs/CONTRACT_CHANGES.md` with what changed and who is affected, (c) updates this file. Never change a schema silently.
6. **Git.** One branch per person (`nafi/…`, `a/…`, `b/…`, `c/…`, `d/…`). Open a PR to `main`; Nafi merges. You only edit paths you own, so merges stay trivial.
7. **Definition of done for every task.** Outputs exist at the exact paths, match the schema, a clean clone reproduces them with the stated command, and the owner can explain the task without notes.
8. **Escalate, don't improvise.** If a Guarantee cannot be met (for example a class has too few rows for 5-fold CV), stop and tell Nafi with the numbers. Do not quietly work around it.
